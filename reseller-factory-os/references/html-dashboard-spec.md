# HTML Dashboard Specification

Use HTML when visual comparison, executive review, beginner selection, or evidence browsing is easier than Markdown.

## Required HTML Qualities

- Single-file HTML when possible.
- Embedded CSS for portability.
- No external script dependency unless explicitly approved.
- Responsive layout.
- Clear Korean labels.
- Decision cards and status badges.
- Accessibility: sufficient contrast, visible focus states, semantic headings, table captions.

## Dashboard Types

1. Factory Control Board: stages, status, active agents, blockers, next approval.
2. UI Style Options: 3-5 selectable visual concepts.
3. Proof Report: pass/fail evidence tables, logs, screenshots placeholders.
4. Release Gate: deployment readiness, rollback, risk summary.

## CSS Style Option Trends

The Market Research Agent should check current UI/CSS trends before finalizing options. Consider:

- Bento grid dashboards.
- Liquid/glass panels with strong readability overlays.
- Enterprise dark mode.
- Soft gradients and subtle motion.
- Dense but readable B2B data tables.
- Command palette / quick action bars.
- Accessible minimalism.

Reject or flag:

- Low-contrast neumorphism.
- Excessive transparency that hurts legibility.
- Heavy animation without reduced-motion fallback.
- Trendy visuals that conflict with B2B trust.
